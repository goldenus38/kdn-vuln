## 5. 데이터 파이프라인 평가 (핵심)

```
CSV file → parseScanCsv() → aggregate() → 자산매칭 → Supabase insert → 집계 렌더
```

| 단계 | 검증 결과 |
|------|-----------|
| **파싱** | 12개 샘플 전수 통과. `""` 이스케이프·한글·콤마 포함 필드 무손실 복원 |
| **집계** | 양호율 = Y/(Y+N)×100, 수동확인(C) 제외 — 수기 계산과 일치 |
| **저장** | Supabase `scans.results`(JSONB)에 67항목 배열 무결성 보존 확인 |
| **대시보드 집계** | 최신 점검 기준 10대 / 취약 135건 / 평균 양호율 76.7% (저장 데이터와 정확 일치) |

> 점검 스크립트의 실제 출력 형식(7컬럼, `${field//\"/\"\"}` 이스케이프)과 파서가 1:1 대응함을 확인.

## 6. 보안 평가 ⚠️ (가장 중요)

취약점 **관리** 시스템이지만, **현재 배포본의 보안 상태는 운영 부적합**이다. 테스트 편의를 위해 의도적으로 완화한 상태이며, 실데이터 투입 전 반드시 원복해야 한다.

| 항목 | 현재 상태 | 위험 | 권고 |
|------|-----------|------|------|
| **인증** | 로그인 게이트 제거(임시) | 누구나 접근 | `Login.tsx` 보존됨 → 인증 복구 |
| **RLS** | `assets`/`scans` RLS **비활성** | 공개 키로 인터넷 누구나 읽기/쓰기/삭제 | RLS 재활성 + authenticated 정책 |
| **API 키** | publishable 키 번들 노출 | (설계상 정상, RLS 전제) | RLS 복구 시 안전 |
| **호스팅** | GitHub Pages(공개) | 자산 IP·취약점 현황 공개 노출 가능 | 내부망/접근제한 호스팅 검토 |
| **민감정보** | 점검 .sh는 저장소 제외 처리 | (내부 이메일 노출 방지 완료) | 유지 |

**결론**: 현재는 *기능 시연 데모* 수준의 보안. 사이버안전센터 실자산 데이터를 다루려면 ① 인증 복구 ② RLS 복구 ③ 비공개/내부망 배포가 선행되어야 한다.

### 결론

KDN-VULN은 주요정보통신기반시설 가이드 U-01~67을 정확히 반영하고, 점검 CSV의 수집·파싱·집계·시각화 파이프라인을 **전수 검증된 수준**으로 완성한 견고한 MVP다. kdn-main의 디자인 자산을 계승해 짧은 기간에 일관된 UI를 확보했고, Supabase 연동까지 동작한다.

다만 **현재 배포본은 테스트를 위해 인증과 RLS를 완화한 데모 상태**이므로, 실제 사이버안전센터 자산 데이터를 다루기 전 ① 로그인 인증 복구, ② Supabase RLS 재활성, ③ 내부망/접근제한 배포를 반드시 선행해야 한다. 기능 측면에서는 조치(fix) 이력 관리와 시계열 추이 분석을 더하면 점검→조치→모니터링 전 주기를 포괄하는 운영 시스템으로 발전할 수 있다.

### 향후 우선순위 (권고)

1. **(필수)** 운영 전 보안 원복 — 인증 + RLS + 비공개 배포
2. **(높음)** 조치(fix) 이력 관리 + 점검↔조치 연계
3. **(높음)** 점검결과서 내보내기(PDF/Excel)
4. **(중간)** 시계열 추이/개선율 그래프
5. **(중간)** 수집 자동화(API push) + 중요도 등급 확정
6. **(낮음)** 코드 스플리팅·단위 테스트·반응형 보강
